## 0. Project context (for Copilot's understanding)

SecretGuard detects leaked credentials in Git history. For Review 2 we build and demonstrate
the **detection baseline (O2)**: extract history → run Gitleaks → classify findings → filter
false positives with a small ML model → report precision/recall/F1 → prove it with unit tests.
Live credential verification (M5), risk scoring (M8), and rotation tracking (M7) come later (O3/O4)
— **do not implement them now**, only leave clean interface stubs where noted.

## Task 0 — Seeded test repository & ground truth (build this FIRST, everything else needs it)

**File**: `testdata/seed_repo.py`

Generate a local Git repository (via GitPython) with ~30 commits. Plant:

- 15 **true secrets**: realistic-looking fake AWS keys (`AKIA` + 16 random chars),
fake GitHub PATs (`ghp_` + 36 chars), fake Stripe test keys (`sk_test_` + 24 chars),
fake Slack tokens, fake generic JWTs — all syntactically valid-looking but **not real,
never call any live API with these in O2**.
- 15 **false-positive lookalikes**: example/placeholder strings from documentation
(e.g. `AKIAIOSFODNN7EXAMPLE` — AWS's own published example key), test fixtures,
random 32-char hex strings that are not credentials, base64-encoded non-secret data.

Write `testdata/ground_truth.yaml`:

```
- commit_sha: <sha>
  file: <path>
  line: <n>
  raw_value_hash: <sha256 of the string>   # never store the raw string itself
  label: true_secret   # or false_positive
  secret_type: aws_access_key            # or github_pat, stripe_key, slack_token, jwt, none
```

**Acceptance**: running `python testdata/seed_repo.py` produces a repo at
`testdata/seeded_repo/` and `testdata/ground_truth.yaml` with exactly 30 labeled entries.

## Task 1 — M1: Git History Extractor

**File**: `backend/extractor/git_history.py`

```
from dataclasses import dataclass
from typing import Iterator

@dataclass
class CommitDiff:
    commit_sha: str
    author_date: str
    file_path: str
    diff_text: str

def extract_history(repo_path: str) -> Iterator[CommitDiff]:
    """Walk the FULL commit history (all branches reachable from HEAD, not just
    the tip) and yield one CommitDiff per changed file per commit.
    Must handle: empty repo (yield nothing, no exception), binary files (skip,
    do not attempt to decode), very large single commits (stream, do not load
    entire repo into memory at once)."""
```

**Unit tests** (`tests/test_git_history.py`):

- empty repo → empty iterator, no exception
- repo with 1 commit, 1 file → exactly 1 CommitDiff
- repo with a binary file committed → binary file is skipped, no crash
- run against `testdata/seeded_repo/` → yields > 0 diffs

## Task 2 — M2: Detection Engine (Gitleaks wrapper + normalizer)

**File**: `backend/detection/gitleaks_runner.py`

```
import subprocess, json
from pathlib import Path

def run_gitleaks(repo_path: str, config_path: str = "gitleaks.toml") -> list[dict]:
    """Invoke the gitleaks binary via subprocess against repo_path with
    `gitleaks detect --source <repo_path> --report-format json --report-path <tmp>`.
    Read the JSON report and return the parsed list of raw findings.
    Must raise a clear RuntimeError (not a bare subprocess exception) if the
    gitleaks binary is not found on PATH, with an actionable message."""
```

**File**: `backend/detection/normalizer.py`

```
from pydantic import BaseModel

class RawFinding(BaseModel):
    commit_sha: str
    file: str
    line: int
    rule_id: str
    matched_string_hash: str   # sha256 — never store the raw matched string in memory longer than needed

def normalize(gitleaks_raw_output: list[dict]) -> list[RawFinding]:
    """Map Gitleaks' native JSON field names (Commit, File, StartLine, RuleID,
    Secret) into RawFinding objects. Hash the Secret field immediately with
    sha256 and discard the plaintext — do not keep it in the RawFinding object
    or in any log line, per NFR-03."""
```

**Unit tests** (`tests/test_gitleaks_runner.py`):

- gitleaks not installed → `RuntimeError` with message containing "gitleaks"
- run against `testdata/seeded_repo/` → returns findings, count > 0
- normalizer never leaves plaintext secret in any returned object (assert no
field on `RawFinding` matches any planted raw secret string)

**File**: `backend/classification/classifier.py`

```
from backend.detection.normalizer import RawFinding
from pydantic import BaseModel

class ClassifiedFinding(BaseModel):
    commit_sha: str
    file: str
    line: int
    secret_type: str
    criticality: int
    matched_string_hash: str

def classify(finding: RawFinding) -> ClassifiedFinding:
    """Map finding.rule_id (Gitleaks rule name) to a canonical secret_type using
    a fixed dict, then look up criticality from criticality_table.yaml.
    Unknown rule_id -> secret_type='generic_high_entropy', criticality=30."""
```

**Unit tests** (`tests/test_classifier.py`): every Gitleaks rule ID appearing in
the seeded repo's ground truth maps to a non-null secret_type and criticality > 0.

## Task 4 — M3b: ML False-Positive Filter (the ML/"AI" component)

**File**: `backend/ml_filter/features.py`

```
import math
from collections import Counter

def shannon_entropy(s: str) -> float:
    """Standard Shannon entropy of the string's character distribution."""

def extract_features(matched_string: str, file_path: str, surrounding_line: str) -> dict:
    """Return a feature dict:
    - entropy: shannon_entropy(matched_string)
    - length: len(matched_string)
    - char_class_count: how many of {lower, upper, digit, symbol} appear
    - digit_ratio: fraction of characters that are digits
    - is_test_path: 1 if file_path contains 'test', 'example', 'fixture', 'mock' (case-insensitive)
    - has_example_keyword: 1 if surrounding_line contains 'example', 'sample', 'dummy', 'placeholder'
    - repeated_char_ratio: fraction of the string that is the single most common character
    """
```

**File**: `backend/ml_filter/train.py`

```
"""
1. Load testdata/ground_truth.yaml.
2. For each entry, reconstruct features via extract_features() — you will need
   seed_repo.py to also dump the raw matched string + surrounding line into a
   SEPARATE local-only file (testdata/_raw_debug.yaml, gitignored, never
   committed) purely so training can compute features; production pipeline.py
   must NEVER depend on this file, only train.py may read it.
3. Split into train (70%) / val (15%) / test (15%) using
   sklearn.model_selection.train_test_split with stratify=labels, random_state=42.
4. Train a RandomForestClassifier(n_estimators=100, random_state=42) on train.
5. Report validation metrics (precision, recall, F1) to stdout.
6. Save the fitted model to backend/ml_filter/model.pkl via joblib.dump.
7. Save the train/val/test split indices to reports/split_indices.json for
   reproducibility.
"""
```
